# RUSTICS — лендинг

## Установка

Скопировать в `client-rust/` с заменой: `src`, `public`, `index.html`.
Файл `api/SteamLogin.cs` — в папку `api` рядом с проектом функций.

После копирования **удалить** `src/index.css` — это дефолтный файл шаблона Vite.
Он ставит на `body` правила `display: flex` и центрирование, из-за которых лендинг
разъезжается. Новый `main.jsx` его уже не подключает.

`pines.js` должен лежать в `src/`, а не в корне проекта.

```bash
npm run dev
```

## Что изменилось в этой версии

**Вход через Steam.** Ник и аватарка больше не тянутся вторым запросом с фронта.
Теперь `SteamLogin.cs` сам ходит за профилем на сервере и возвращает всё одним
редиректом. Раньше при недоступной функции фронт молча показывал `ID 991334` —
теперь такой точки отказа нет, а заодно исчезли CORS и лишний эндпоинт.
`SteamProfile.cs` больше не нужен, его можно удалить.

Появилась кнопка **Выйти** рядом с профилем. Раньше выход происходил неявно.

**Данные сервера** взяты из описания в игре, а не выдуманы:
рейт X1, NO LIMIT на состав, 200 слотов, карта 4000, содержание шкафа /2,
вайп каждую субботу в 12:00 МСК.

**Правила переписаны.** В прошлой версии было «максимум 5 человек в группе», что
прямо противоречило NO LIMIT в описании сервера. Пункт убран вместе с правилом про
тиминг. Добавлены обход бана и порядок подачи жалоб.

**Видео получило работу.** Вертикальный ролик раньше показывался только на телефоне.
Теперь на десктопе он же работает карточкой сервера в разделе «Классика X1» —
в своём родном вертикальном формате, как карточка в списке серверов Rust.
На узких экранах карточка скрывается, чтобы ролик не дублировался.

**Подвал** переделан в четыре колонки со ссылками и копированием IP.
Строка «Не аффилирован с Facepunch Studios» убрана.

## Тексты и языки

Все тексты сайта лежат в `src/text.js` — русский и английский рядом, одинаковой
структурой. В `App.jsx` текста нет вообще, только разметка: править формулировки
можно, не заглядывая в код.

Переключатель в шапке меняет язык всей страницы разом, включая заголовок вкладки,
описание для поисковиков и атрибут `lang` у `<html>` — по нему ориентируются
читалки и встроенный переводчик браузера. Выбор запоминается, так что
англоязычному игроку не придётся переключаться при каждом заходе.

Правила пронумерованы как «раздел.пункт» (1.1, 1.2, 2.1) — на такой номер можно
сослаться в чате или в Discord, разбирая жалобу.

При добавлении фразы её надо положить **в оба языка**: недостающий ключ просто не
отрисуется, и на странице окажется пустота.

## Что поменять перед сдачей

Всё правится в объекте `CFG` в начале `src/App.jsx`.

| Поле | Что это |
|---|---|
| `serverIp`, `serverPort` | Адрес сервера. Сейчас стоит заглушка |
| `api` | Путь до функций. Теперь это `/api` на том же домене, что и сайт — менять не нужно (см. «Настройка функции») |
| `discord`, `telegram` | Ссылки на сообщества |
| `serverName` | Название сервера на карточке |

Тексты — массивы `RATES`, `FEATURES` и `RULES` там же.

## Настройка функции

В `local.settings.json` в секцию `Values`:

```json
"STEAM_API_KEY": "ключ с steamcommunity.com/dev/apikey",
"SITE_URL": "http://localhost:5173,http://127.0.0.1:5173"
```

`SITE_URL` — белый список адресов, куда функции разрешено возвращать игрока.
Можно перечислить через запятую. Сам адрес возврата берётся из `openid.return_to`,
то есть с того сайта, где нажали «Войти», — поэтому одна функция обслуживает
и localhost, и прод. Чужие адреса в список не попадают и молча уводятся на первый
из `SITE_URL`, чтобы не получился открытый редирект. Локальные адреса разрешены
всегда, отдельно прописывать их для разработки не нужно.

Без `STEAM_API_KEY` вход всё равно работает, но вместо ника показывается
`Игрок 91334` — это штатный запасной вариант, а не ошибка. Функция пишет об этом
в лог, так что молчаливого сбоя больше нет.

### Функции и сайт должны жить на одном домене

Steam требует, чтобы адрес возврата (`openid.return_to`) лежал внутри `openid.realm`,
а `realm` — это домен сайта. Поэтому `/api` обязан быть на том же домене:
в разработке это делает прокси в `vite.config.js` (5173 → 7071), на проде — Static
Web Apps, который сам поднимает `/api` рядом с сайтом. Если функции когда-нибудь
переедут на отдельный домен, вход через Steam придётся переделывать.

### Онлайн сервера

Счётчик идёт из мастер-листа Steam, а не из BattleMetrics: их API теперь требует
подписки и отвечает 403, а страницу сайта закрывает Cloudflare. Rust-сервер и так
публикует себя в Steam, так что источник первичный и бесплатный — и тем же ключом,
который уже нужен для входа.

В `local.settings.json`:

```json
"SERVER_HOST": "195.18.27.169",
"SERVER_PORT": "35100"
```

`SERVER_PORT` — игровой порт (не порт запроса). На одном IP у хостера стоят и чужие
серверы, поэтому выдача Steam фильтруется по appid Rust и по этому порту.

Ответ `/api/server/status` кэшируется на 30 секунд на весь процесс, фронт
перезапрашивает раз в минуту. Steam при этом получает пару запросов в минуту
независимо от того, сколько человек открыли страницу.

В ответе есть поле `bornAt` — метка `born` из тегов Steam, момент, с которого живёт
текущий мир. **На сайте она не показывается.** По состоянию на 4 сентября 2026 она
равна `2026-09-03 20:56 МСК`, тогда как вайп заявлен на 12:00 — то есть это, скорее
всего, последний перезапуск, а не вайп. Прежде чем показывать её как дату вайпа,
сверьте с двумя-тремя известными вайпами.

### Список игроков и часы

Раздел «Топ игроков» берёт данные **напрямую с игрового сервера** по протоколу
запроса Steam (A2S) — тем же, которым сервер опрашивает и сам BattleMetrics.
Порт запроса публичный, поэтому не нужны ни подписка, ни доступ к машине сервера,
ни чей-либо API. Эндпоинт: `/api/server/players`, кэш 30 секунд.

В `local.settings.json`:

```json
"SERVER_QUERY_PORT": "35110"
```

Это **порт запроса**, а не игровой: у Rust он обычно на 10 больше (35100 → 35110).
Точное значение видно в выдаче Steam в поле `addr`.

**Важно: A2S у нашего сервера отдаёт выдуманный список.** Ники в ответе не совпадают
с теми, кто реально в игре (проверено через консоль 16.09.2026), и даже число игроков
расходится с мастер-листом Steam. Поэтому, если задан RCON, и `/api/server/players`,
и накопление статистики берут список **только из WebRCON** (команда `playerlist`),
а к A2S не откатываются — лучше «недоступно», чем фальшивые ники:

```json
"RCON_PORT": "35101",
"RCON_PASSWORD": "…"
```

Пароль RCON даёт полный доступ к консоли сервера: только в `local.settings.json`
(он в .gitignore) или в настройках хостинга, никогда в git и не в GitHub Actions без
крайней нужды.

**Что именно показывает таблица.** Сервер отдаёт время текущей сессии игрока —
сколько он не выходил, — а не общий налёт за всё время. Поэтому подпись в разделе
говорит «кто дольше всех в игре прямо сейчас», а не «топ за всё время». Чтобы
считать общий налёт, эти замеры надо копить в хранилище: опрашивать сервер по
таймеру и складывать минуты по каждому игроку. Это отдельная работа, и считать
она начнёт с момента запуска.

**Осторожно при деплое.** A2S работает по UDP, а песочница Azure App Service
исходящий UDP режет. Локально всё работает (проверено), после деплоя на Functions
список может отвалиться — тогда этой части нужен хостинг, где UDP разрешён.
Счётчик онлайна от этого не пострадает: он идёт из Steam по HTTP, и это одна из
причин, почему источники намеренно оставлены разными. Из-за разной свежести
счётчик и таблица могут на один цикл обновления расходиться на игрока — это норма.

### Своя история: часы за период и график

Сервер помнит только «сейчас». Всё остальное, что показывает BattleMetrics —
таблицу «Наибольшее время игры» и графики численности, — он не берёт откуда-то ещё:
он годами опрашивает сервер и складывает замеры у себя. Здесь сделано то же самое.

Опрос идёт **каждые пять минут**, время начисляется по самому факту присутствия
игрока в списке, а не по полю сессии: так переподключения и странные значения
сессии не искажают итог. Если опроса не было дольше 15 минут, промежуток не
начисляется — иначе простой службы превратился бы в часы игры.

| Эндпоинт | Что отдаёт |
|---|---|
| `/api/server/players` | Кто сейчас в игре и сколько длится сессия |
| `/api/server/top` | Накоплено за всё время наблюдения |
| `/api/server/top?period=month` | То же за 30 дней |
| `/api/server/history?hours=24` | Численность во времени, для графика |

На сайте это три вкладки — «Сейчас», «Месяц», «За всё время» — и график над ними.

**История начинается с момента запуска.** Задним числом её взять негде, так что
первые дни вкладки периодов будут пустыми — это не поломка, и подпись под таблицей
говорит об этом прямо, называя дату начала наблюдения.

Копится в обычном JSON-файле: для лендинга с парой сотен игроков база избыточна,
а файл переживает перезапуск и не тянет за собой ни зависимостей, ни настройки.
Путь задаётся `STATS_PATH`; по умолчанию — папка `HOME/data/rustics` (на Azure она
постоянная), а если её нет — рядом с бинарником. Записи старше 14 дней сворачиваются
в одну строку `before`, чтобы файл не рос без предела, но общий налёт не терялся.

Шаг опроса можно ускорить через `STATS_POLL_MINUTES` — пригодилось при проверке,
когда ждать пять минут ради второго замера было нечем.

**Почему опрос не на таймере функций.** Таймеру нужна учётка хранилища: локально
без Azurite его слушатель не стартует вовсе (`Unable to access AzureWebJobsStorage`).
Поэтому опрос делает фоновая служба `StatsPoller` — она ни от чего не зависит и
работает сразу, без установки лишнего. Таймер `StatsPoll` тоже оставлен: на проде
учётка есть, и он подстрахует, если приложение уснёт. Двойной замер безвреден —
время считается по промежутку, так что второй подряд начислит около нуля.

### Откуда берётся список игроков

Из **WebRCON** игрового сервера, команда `playerlist` (см. `api/Rcon.cs`). Публичный
запрос A2S у этого сервера отдаёт выдуманный список: ники не совпадают с теми, кто
реально в игре, и даже число игроков расходится с мастер-листом Steam — проверено
16.09.2026 сверкой с консолью сервера.

Прокси к BattleMetrics (`/api/bm/*`) удалён. Их API требует платную подписку и
отвечает 403, данные оттуда всё равно не приходили, а диагностический эндпоинт
`/api/bm/diag` был открыт всем и показывал наружу настройки бекенда.

### Запуск бэкенда локально

```bash
cd api
func start
```

В списке при старте должны появиться: `SteamLogin`, `ServerStatus`, `PlayerList`,
`StatsTop`, `StatsHistory`, `BmServer`, `BmTop`, `BmDiag` и таймер `StatsPoll`.
Строку про `StatsPoll: The listener ... was unable to start` локально можно
игнорировать — это он не нашёл Azurite, замеры делает фоновая служба.
Если вместо них написано `No job functions found` — значит в `api.sln` снова затянуло
сгенерированный `WorkerExtensions.csproj` из `obj/`. В решении должен быть только
`api.csproj`, иначе сборка идёт мимо и функции не регистрируются.

## Развёртывание

### Главное, что решает всё остальное

Половина возможностей держится на **исходящем UDP**: список игроков и накопление
статистики идут по протоколу запроса Steam. Песочница Azure App Service исходящий
UDP режет. Значит на Azure Functions заработают вход через Steam и счётчик онлайна
(они ходят по HTTP), а раздел «Топ игроков» останется пустым.

Отсюда два пути.

### Где хостить бесплатно

Бесплатных вариантов, где проходит исходящий UDP, немного, и они меняются.
На сентябрь 2026:

| Площадка | Годится | Почему |
|---|---|---|
| **Oracle Cloud Always Free** | да, рекомендую | Настоящая виртуалка, бессрочно бесплатно, 10 ТБ трафика |
| Google Cloud e2-micro | как запасной | Бессрочно, но только регионы США и **1 ГБ трафика в месяц** |
| Fly.io | нет | Бесплатный тариф закрыт для новых аккаунтов |
| Vercel, Netlify, Cloudflare Workers | нет | Бессерверные — UDP не дают в принципе |
| Azure Functions | частично | UDP режет: вход и онлайн будут, топ игроков нет |

У Oracle есть подвох: в выбранном регионе может не оказаться свободных ARM-машин
(Ampere A1). Тогда берите две маленькие AMD-микромашины — их обычно хватает, и
нашему приложению 1 ГБ памяти достаточно.

**И у Oracle, и у Google регистрация требует зарубежной карты.** Если её нет,
остаются два пути.

**Дешёвый российский VPS.** Порядка 150–300 ₽ в месяц у Timeweb, Beget, RuVDS,
aeza, VDSina — оплата российской картой. Разворачивается связкой из `deploy/`
как есть. Для боевого сайта клиента это правильный вариант: хостинг — расходная
часть проекта, а не место для экономии.

**Cloudflare Tunnel и своя машина — бесплатно и без карты.** `cloudflared`
соединяется с Cloudflare изнутри наружу, поэтому не нужны ни белый адрес, ни
проброс портов, ни открытый 443. Сертификат даёт Cloudflare, домен переводится
на его серверы имён (тариф Free). Запуск:

```bash
docker compose -f docker-compose.yml -f docker-compose.tunnel.yml up -d --build
```

В панели Cloudflare (Zero Trust → Networks → Tunnels) создать туннель, направить
домен на `http://web:80` и положить токен в `TUNNEL_TOKEN`.

Единственное условие — **машина должна работать круглосуточно**. Ноутбук не
подойдёт: статистика копится только пока идёт опрос, а промежутки больше
15 минут не засчитываются. Закрыли крышку — в истории дыра.

### Домен и HTTPS

Зона домена к хостингу отношения не имеет: `.com` так же спокойно указывает на
российский VPS, как и `.ru`. Разница только в регистраторе и цене. Российские
регистраторы (reg.ru, timeweb, beget) продают `.com` и принимают карты РФ — это
удобно, если зарубежной карты нет.

Сайт и бэкенд живут на **одной машине и одном домене**. Так надо: Steam возвращает
игрока по адресу из `openid.return_to` и сверяет, что тот лежит внутри realm.

**DNS.** Две A-записи на адрес VPS:

```
@     A    <IP сервера>
www   A    <IP сервера>
```

Обновление занимает от нескольких минут до пары часов. **Записи должны заработать
до первого запуска** — Caddy получает сертификат проверкой через домен, и если тот
ещё не резолвится, попытка провалится.

**HTTPS.** Отдельно делать ничего не нужно: Caddy получает сертификат Let's Encrypt
сам и сам продлевает. Требуется лишь открытые 80 и 443 — и в самой системе, и в
файрволе провайдера (у российских VPS это обычно отдельная настройка в панели).

**www уводится редиректом** на основной адрес. Это не косметика: вход через Steam и
профиль игрока хранятся браузером отдельно для каждого адреса. Работай сайт и на
`www`, и без него — человек, зашедший на другой вариант, увидел бы себя
разлогиненным и решил, что сайт сломался.

### Развёртывание на своей машине или VPS

В папке `deploy/` лежит готовая связка: Caddy отдаёт собранный фронт, сам получает
сертификат Let's Encrypt и проксирует `/api` в контейнер функций. Всё на одном
домене — это требование Steam, а не удобство: он сверяет, что адрес возврата лежит
внутри realm.

Порядок на чистой Ubuntu:

```bash
# 1. docker
curl -fsSL https://get.docker.com | sh

# 2. проект целиком — вместе с api/, deploy/ и ReactFrond/
#    (scp, rsync или git clone)

# 3. собрать фронт
cd ReactFrond/client-rust && npm ci && npm run build

# 4. настройки и запуск
cd ../../deploy && cp .env.example .env    # заполнить
docker compose up -d --build
```

Если на сервере мало памяти и сборка фронта не проходит — соберите `npm run build`
у себя и загрузите готовую папку `dist` в `ReactFrond/client-rust/`. Compose
монтирует именно её, node на сервере для этого не нужен.

История статистики лежит в томе `stats` и переживает обновление образа. Опрос
ведёт фоновая служба `StatsPoller`, учётка хранилища проекту не нужна вовсе.

**`AzureWebJobsStorage` должна оставаться пустой.** Если хост пытается достучаться
до хранилища и не может, он не просто пишет ошибку в лог — он уходит в состояние
`Unhealthy` и **перестаёт отвечать на запросы**. Выглядит это обманчиво: функции
в списке при старте есть, порт слушается, а любой запрос висит до таймаута.

### Развёртывание на Azure Functions

Годится, если топ игроков пока не нужен. Из папки `api`:

```bash
func azure functionapp publish ИМЯ-ПРИЛОЖЕНИЯ
```

Настройки из `local.settings.json` **не уезжают** вместе с кодом — их надо прописать
в Function App руками (Configuration → Application settings):

| Настройка | Значение |
|---|---|
| `STEAM_API_KEY` | ключ с steamcommunity.com/dev/apikey |
| `SITE_URL` | боевой адрес сайта, https, без слэша на конце |
| `SERVER_HOST` | `195.18.27.169` |
| `SERVER_PORT` | `35100` — игровой порт |
| `SERVER_QUERY_PORT` | `35110` — порт запроса |
| `RCON_PORT` | `35101` — порт WebRCON |
| `RCON_PASSWORD` | пароль RCON: полный доступ к консоли сервера, только в настройках, никогда в git |
| `FUNCTIONS_WORKER_RUNTIME` | `dotnet-isolated` |

**`STATS_PATH` в Azure задавать не надо.** В `local.settings.json` он указывает на
папку конкретного компьютера; без него код возьмёт постоянную папку `HOME`, которая
на Azure переживает перезапуски.

После выкладки проверить, прошёл ли UDP:

```
https://ИМЯ-ПРИЛОЖЕНИЯ.azurewebsites.net/api/server/players
```

Список игроков — UDP работает. `server_silent` — не работает, и топ игроков на этом
хостинге не поднять.

## Что осталось уточнить у клиента

- **Показывать ли пустые вкладки периодов** первые дни, пока копится история, или
  прятать их до появления данных
- **Ссылки на Discord и Telegram**
- **Вайп чертежей.** В описании сервера написано «вайп каждую субботу кроме первого
  четверга нового месяца». Я истолковал это как: карта вайпается по субботам, а в
  первый четверг месяца идёт общий вайп Rust вместе с чертежами. Стоит подтвердить,
  прежде чем показывать клиенту
- **Что считать «топом игроков».** Задумано было время на сервере. Топ по убийствам
  требует плагина статистики на самом сервере и в согласованный объём работ не входит.
  Учитывая, что бесплатный источник времени тоже отпал, плагин на сервере закрывает
  сразу оба вопроса — стоит обсудить его вместо подписки
